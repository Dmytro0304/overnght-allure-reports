# Тест-кейсы: таймзона пользователя и оплата подписки (Stripe)

Документ основан на анализе кода (`AccountSettings.tsx`, `useTimezone.ts`, `auth` `/me`, `users.platform.service`, checkout `s/start`, `resubscribe`, `Promocode`, Stripe).

**Пакеты подписки (2):** Monthly **$11.99** (`PlanType.MONTHLY`), Annual **$104.99** (`PlanType.ANNUAL`) — `web/src/utils/plan.ts`.

**Купон для проверки:** `MARIA2025` (ожидается promotion code в Stripe с ~10% скидкой; если в Dashboard кода нет — кейс «невалидный купон»).

## Часть A — Таймзона

### Анализ поведения (код)

| Ожидание продукта | Как реализовано |
|-------------------|-----------------|
| Новому пользователю по умолчанию — таймзона **устройства** | В `/me` поле `settings.timezone` = **`null`**, пока нет записи в БД (`getSettingValue`). В `useTimezone()` при `!tz` возвращается **`BROWSER_TIMEZONE`** (`Intl` на клиенте). |
| Можно переключить на выбор из списка | В **Account → Settings**: переключатель **Device Timezone** OFF → выпадающий список + поиск + пункт **Event Timezone** (`platform`). Выбор зоны вызывает `PATCH` настроек с IANA или `platform`. |
| Включить обратно «как на устройстве» | Переключатель ON → `deleteSetting('TIMEZONE')` → снова `null` → снова поведение как у нового пользователя (девайс). |
| Явное `auto` в API | Допустимо на бэкенде (`UserTimezone.AUTO`); в UI режим «устройства» соответствует **`null` или `auto`** (`serverIsDevice`). |

**Подсказка-баннер:** `TimezoneSuggestBar` показывается только если **`savedTz` задан** (не `null`) и путь не `/auth/*`, `/legalese/*`, `/account` (`TimezoneSuggestProvider.tsx`).

### TC-TZ-001 — Новый пользователь: отображение времени как на устройстве

**Предусловия:** Свежий аккаунт без ручных правок timezone в БД; известна таймзона браузера (например Europe/Kyiv).

**Шаги:**

1. Залогиниться под новым пользователем.
2. Открыть **My Account** → **Settings** (на мобильной вкладке **Settings**).
3. Убедиться, что **Device Timezone** включён, в строке **Timezone** отображается город/аббревиатура, соответствующая **текущему браузеру** (`BROWSER_TIMEZONE`).
4. Открыть главную и страницу поиска с событиями с известным `event.timezone`.
5. Сверить, что время/дата на карточках согласованы с логикой `useTimezone` + `resolveEventTz` (для `null` — подстановка девайса).

**Ожидаемый результат:** Нет сохранённой записи TIMEZONE → UI и карточки ведут себя как **device timezone** (не фиксированный IANA с сервера).

---

### TC-TZ-002 — Переключение на фиксированную IANA и проверка Home/Search

**Предусловия:** Пользователь как в TC-TZ-001.

**Шаги:**

1. **Settings** → выключить **Device Timezone**.
2. В списке выбрать зону, отличную от девайса (например **America/New_York**).
3. Дождаться сохранения (запрос настроек без ошибки).
4. Обновить главную и поиск; сравнить отображаемое время с предыдущим шагом.

**Ожидаемый результат:** Время на листингах отражает **выбранную IANA** (и при необходимости вторичную строку «времени события» по коду карточек).

---

### TC-TZ-003 — Event Timezone (`platform`)

**Шаги:**

1. Выключить **Device Timezone**, открыть селект.
2. Выбрать **Event Timezone** (value `platform`).
3. Открыть событие, у которого задан свой `event.timezone`.

**Ожидаемый результат:** `useTimezone()` для `platform` отдаёт `undefined` → отображение опирается на **таймзону события** (см. `EventCard`, `ShowCard`).

---

### TC-TZ-004 — Поиск в списке таймзон

**Шаги:** При открытом селекте ввести в **Search...** подстроку города или IANA (например `Kyiv`, `London`).

**Ожидаемый результат:** Список фильтруется по `label` и `value`; можно выбрать отфильтрованную зону.

---

### TC-TZ-005 — Возврат к таймзоне устройства

**Шаги:**

1. После TC-TZ-002 включить **Device Timezone** снова.
2. Обновить страницу аккаунта.

**Ожидаемый результат:** Снова режим девайса; в API для timezone снова отсутствует явная запись (или поведение эквивалентно `null` после `delete`).

### TC-TZ-006 — Баннер подсказки (если включён у вендора)

**Шаги:** Установить любую **непустую** таймзону (не `null`). Открыть главную (не `/account`).

**Ожидаемый результат:** При наличии `savedTz` может отображаться `TimezoneSuggestBar` (проверить текст и закрытие).

## Часть B — Оплата подписки (Stripe, тестовые карты)

Используйте **Stripe test mode** и ключи из `.env`. Официальные тестовые номера: [Stripe testing](https://docs.stripe.com/testing#cards).

| Сценарий | Номер карты | Ожидание |
|----------|-------------|----------|
| Успех | `4242 4242 4242 4242` | Подписка активируется, редирект/успех UI |
| Отклонение | `4000 0000 0000 0002` | Сообщение об ошибке, деньги не списаны |
| Недостаточно средств | `4000 0000 0000 9995` | Ошибка от Stripe |
| 3DS (если включено) | `4000 0025 0000 3155` | Поток подтверждения |

**Срок / CVC:** любая будущая дата, любой 3-значный CVC (в тесте).

**Купон:** поле **Coupon Code (Optional)** → **Apply** вызывает `POST .../subscriptions/coupon/validate` с телом `{ code }`; при успехе в создание подписки уходит **`coupon: promoCode.id`** (id promotion/coupon из Stripe).
